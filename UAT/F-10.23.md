## Aggregate-only reactions

Alice sends a DM. Alice adds 👍 twice, then Bob adds 👍.

Expected: duplicate add is idempotent; one reaction row exists per user/message/value; both participants see aggregate count 2. Each user receives only their own `reacted_by_me` state. No participant identity list is present in API/UI.

Test all allow-listed values: 👍 ❤️ 🎉 👀 ✅. Arbitrary emoji must be rejected.

## Privacy / epoch

As the nonparticipant Owner/Admin, try to add/remove a reaction to Alice/Bob's message.

Expected: fail closed without message existence leakage.

Downgrade Alice, restore her role and explicitly re-initiate the DM. Try to react to a message from Alice's old hidden visibility epoch.

Expected: old target remains 404/hidden. New-epoch messages can be reacted to normally.

## Retraction / retention

Add a reaction, then retract the message.

Expected: reaction rows cascade away; the tombstone exposes no reactions and new reaction attempts fail. Repeat with private-message retention on an aged reacted message; message deletion must cascade the private reaction rows. Legal hold must continue blocking the private-message purge.
