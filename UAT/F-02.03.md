## Backend / real-data validation

1. Sign in as a Brain Owner/Admin and start the GitHub install flow.
2. Confirm GitHub shows the expected Brain GitHub App and only the intended repository selection.
3. Complete OAuth and verify Brain offers only installations accessible to the authenticated GitHub user and belonging to the configured Brain GitHub App.
4. Connect one installation. Confirm PostgreSQL contains a `github` integration connection with installation/account metadata and **no installation access token**.
5. Attempt the generic `POST /organizations/{org}/integrations` flow with `provider=github`; confirm it is rejected.
6. Trigger a real push, pull request and issue event in a selected repository. Confirm each signed webhook creates one raw event and one canonical event.
7. Redeliver the same GitHub delivery (GitHub redelivery or controlled replay). Confirm row counts do not increase for that delivery.
8. Send/attempt an invalid webhook signature. Confirm HTTP 401 and no raw/canonical record is created.
9. For a private repository, confirm raw and canonical evidence carry `github:repository:<id>` and are not marked public.
10. Run backfill. Confirm repository metadata, commits, pull requests, issues and deployments are traversed with a persisted cursor.
11. Resume from the cursor after interrupting the process. Confirm it continues rather than restarting silently.
12. Replay a previously processed cursor/page. Confirm deterministic source IDs prevent duplicate raw/canonical records.
13. Revoke or remove the GitHub App installation and confirm future sync cannot continue as though the installation were healthy.
14. Inspect logs. Confirm private keys, client secret, webhook secret and installation tokens do not appear.

## Frontend / manual validation

The production frontend flow must allow an authorised Owner/Admin to:

- start GitHub connection
- see installation choices returned after GitHub authentication
- select/connect an installation
- see connection health/account/repository-selection state
- start or resume backfill where exposed
- see useful loading, empty, success and failure states
- understand when GitHub permission/reinstallation is required

Verify a Member/Guest cannot access integration-management controls.
