# F-02.02 Slack Connector UAT

Status: **UAT_PENDING**

Engineering automation is not customer acceptance. Run this against a dedicated realistic Slack workspace before changing the status to ACCEPTED.

## Preconditions

- deployed Brain backend with migration `20260906_0005` applied;
- real WorkOS login for an owner/admin and a lower-privilege member;
- dedicated Slack app/workspace configured from `docs/SLACK_SETUP.md`;
- real AWS Secrets Manager access for the backend;
- no real employee/customer-sensitive messages are required for this test; use realistic synthetic company messages;
- a public test channel and a private test channel containing multiple test users;
- Brain Slack app invited to both channels.

## Real-data backend validation

1. As owner/admin, start Slack installation and complete the real OAuth flow.
2. Confirm the connection record contains the real Slack workspace ID and granted scopes but no token/secret value.
3. Confirm AWS Secrets Manager contains the bot credential under the Brain integration path.
4. List Slack channels. Confirm public/private test channels appear and DMs do not appear as authorisable resources.
5. Authorise the public test channel and private test channel explicitly.
6. Confirm the private-channel authorisation stores the expected Slack member IDs.
7. Post a realistic message in each authorised channel. Confirm each becomes exactly one `raw_events` row with the correct organisation/connection, Slack `event_id`, exact payload checksum and visibility.
8. Trigger/replay the same Slack delivery or resend the same captured event ID. Confirm the database still contains only one row for that source event.
9. Post into an unauthorised test channel. Confirm Brain acknowledges/ignores it and stores no raw event.
10. Add/remove a test member in the authorised private channel. Confirm the persisted private-channel ACL state updates.
11. Run one backfill page. Confirm raw historical messages are inserted with deterministic IDs and a cursor is saved.
12. Run another page / replay with reset. Confirm existing messages are deduplicated.
13. Remove a channel authorisation and send another message in that channel. Confirm no new raw event is stored.
14. Revoke the Slack connection. Confirm it becomes non-syncable and subsequent deliveries are ignored.
15. Review application logs. Confirm no bot token, signing secret, OAuth code, raw credential or sensitive secret is logged.

## Negative/security validation

- Repeat install/channel-management requests as a normal member and confirm 403.
- Attempt an invalid/tampered OAuth state and confirm callback rejection.
- Send an invalid Slack signature and confirm 401 with no raw record.
- Send a correctly signed request with a timestamp older than five minutes and confirm rejection.
- Attempt to authorise a DM/MPDM and confirm rejection.

## Frontend/manual validation

This acceptance section remains PENDING until Brain's production frontend exposes the real authenticated Slack admin flow. When it does, verify:

- Connect Slack action and OAuth redirect/callback;
- loading, cancelled OAuth, provider-error and success states;
- channel list pagination/loading/empty/error states;
- explicit private/public channel selection with clear privacy wording;
- backfill progress/status;
- revoke/disconnect flow and confirmation;
- keyboard accessibility, focus states and readable error messages;
- UI never displays provider tokens/secrets.
