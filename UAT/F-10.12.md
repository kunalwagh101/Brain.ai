# F-10.12 Author-safe Message Lifecycle UAT

Story: `S-10.12.01`

Status: implementation in progress. No DONE/PASS claim until executable gates and authenticated browser evidence exist.

## Product acceptance

1. Author posts a Brain channel message, edits it, and sees the new text with an edited marker without manual reload.
2. Edit updates Search results: old unique sentinel disappears, new sentinel appears. Edited content resolves to a new CanonicalEvent/RawEvent revision; the prior canonical event is unchanged and the previous SearchDocument version is retired.
3. Edit removes an @mention and that user's current Activity mention disappears; adding a valid authorised mention becomes visible without duplicates.
4. Two edit clients start from the same revision. The first succeeds; the second receives conflict and does not overwrite the first.
5. Another member, Owner/Admin/Executive, guest, revoked member and cross-tenant actor cannot edit or retract the author's message merely because of role or identifier knowledge.
6. Human cannot edit/retract an agent-authored message.
7. Author retracts a root message. Conversation shows a body-free tombstone; Search no longer returns the content; unread count excludes it.
8. Existing replies under a retracted root remain readable. New reply/reaction/edit against the retracted root is rejected. Retraction creates its own immutable canonical lifecycle event while all message SearchDocument versions remain deleted.
9. Retracting a reply hides that reply body and message-derived Activity while preserving the root/thread.
10. API/BFF responses for a retracted message do not expose its prior body, body hash, mentions or reactions.
11. Audit entry contains IDs, revision transition and hashes only—no plaintext body.
12. Restricted-channel membership removal removes current and historical message-revision Work Graph grants. WorkOS browser mutations use same-origin routes and expose no reusable bearer token.
