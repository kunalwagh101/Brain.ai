## Backend validation

1. Apply migrations through `20260907_0012` against PostgreSQL.
2. Configure one real governed AI provider/model through F-06.01.
3. Create a rate card from an approved provider pricing source. Record the source label and independently calculate the expected nano-USD/token values.
4. Make at least three real provider requests with provider-returned token usage.
5. Verify each successful `ai_request_record` has exactly one `ai_usage_cost_record`.
6. Independently calculate expected request cost from returned input/output token counts and configured rate. Compare to Brain's persisted nano-USD total. Expected: exact integer match.
7. Run a provider/model configuration without a usable effective rate. Expected: request succeeds, cost status is `unknown`, reason is `rate_card_unavailable`, and total cost remains NULL rather than zero.
8. If the provider can omit usage metadata in a controlled test, verify `token_usage_unavailable` behaves the same way.
9. Add the missing historical rate and run:

   ```bash
   cd backend
   python -m app.ai_usage_worker --once --batch-size 100
   ```

   Expected: eligible rate-card-unknown records become `calculated` without duplicating cost rows.
10. Create organisation, provider, model, user and Work Graph node budgets. Attempt a cross-tenant target. Expected: rejected before persistence.
11. Configure a warning threshold low enough to cross in test traffic. Re-evaluate/replay multiple times. Expected: only one alert for `budget + month + threshold`.
12. Cross 100%. Expected: one 100% alert, not duplicates.
13. Enable hard-stop. After known spend is at/above the limit, invoke again. Expected: request is rejected before secret lookup/provider execution.
14. Verify a period containing unknown-cost requests reports `enforcement_complete=false`.
15. Verify usage summary by provider, model, user and Work Graph node. A request with no attribution node must remain in a NULL/unknown attribution group.
16. Verify ordinary Member cannot read organisation-wide usage/cost endpoints; Owner/Admin/Executive with `audit.read` can.
17. Search application logs/database for the test API key and sensitive test prompt. Expected: neither appears in cost/budget records or logs.
18. Run two reconciliation workers concurrently on PostgreSQL with a backlog. Expected: `FOR UPDATE SKIP LOCKED` prevents duplicate processing and the request unique constraint prevents duplicate cost rows.
19. Downgrade revision `20260907_0012`. Expected: AI request ledger remains; only rate/cost/budget/alert derived tables are removed.
20. Re-upgrade and reconcile. Expected: cost state can be rebuilt from the preserved AI request ledger plus configured historical rates.
