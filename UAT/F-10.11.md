# F-10.11 Workspace Search & Quick Switcher UAT

Story: `S-10.11.01`

Status: implementation in progress. No PASS/DONE claim until executable gates and authenticated browser UAT pass.

## Product acceptance

1. Ctrl+K and Cmd+K open the dialog from the authenticated workspace and focus the search input.
2. Escape closes the dialog and focus can return to normal workspace navigation.
3. Empty query shows only currently visible local navigation choices: Brain channels, projects, tracks and participant-visible DM counterparts.
4. A two-character query triggers a debounced same-origin keyword search; one-character and empty queries do not call the remote search route.
5. Brain-native channel message text can be found only when the current user can still read that channel.
6. Opening a Brain-native message result routes to its exact channel/message context.
7. Removing restricted-channel access and repeating the same search returns zero results from that channel.
8. Private/restricted Slack/GitHub/evidence results obey the existing Search authorization contract.
9. A participant can find a DM counterpart by visible name/email and open that conversation.
10. A distinctive string present only inside a DM body returns zero organisation-wide remote search results.
11. Loading, no-results and error states remain keyboard-operable and do not expose raw upstream error bodies.
12. Search result text is bounded in the dialog; provenance/source labels remain visible.

## Security/privacy inspection

- browser search component contains no `Authorization`, `Bearer`, access-token or browser-storage credential handling;
- BFF uses `withAuth()`, revalidates Brain organisation membership and accepts only bounded query/mode/limit values;
- remote response is `Cache-Control: no-store, private`;
- no DM message body enters the organisation-wide search result contract;
- revoked/restricted results are not cached client-side as an authority source.
