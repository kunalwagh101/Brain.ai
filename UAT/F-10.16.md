# F-10.16 Personal Saved Messages UAT

Story: `S-10.16.01`

Status: implementation in progress. No DONE/PASS claim until executable gates and authenticated browser evidence exist.

## Product acceptance

1. As an authorised channel reader, save a normal root message and confirm it appears once in your Saved surface.
2. Save the same message repeatedly/concurrently and confirm one database row and one Saved item.
3. Save a thread reply and open it from Saved; confirm Brain opens the correct channel/thread/reply context.
4. Save a visible agent-authored message and confirm it succeeds without granting human edit/retract rights.
5. Edit a saved human message and confirm Saved resolves to the current edited message while the save identity remains unchanged.
6. Retract a saved human message and confirm its saved reference is removed in the same lifecycle.
7. In a restricted channel, revoke the saving user and confirm the next Saved read omits the inaccessible message.
8. Restore channel access and confirm the content-free saved reference may become visible again if the message still exists.
9. Sign in as a second user, Owner/Admin/Executive included, and confirm they cannot see or mutate the first user's saved state.
10. Confirm save rows/API add no copied message body, attachment bytes or evidence excerpts.
11. Confirm Save/Unsave and Saved-list browser traffic is same-origin WorkOS traffic with no reusable backend bearer token.
12. Run migration upgrade/downgrade/re-upgrade and confirm only saved-reference rows/table are affected.

## Required executable evidence

- focused backend privacy/idempotency/revoke/retract tests;
- Alembic single-head + PostgreSQL upgrade/downgrade/re-upgrade;
- `npm run lint` and `npm run build`;
- `node --test tests/saved-messages-contract.test.mjs` and full frontend contracts;
- `python scripts/verify_board.py`;
- official WorkOS authenticated multi-user desktop/mobile/keyboard UAT.

Until every required gate passes, keep `S-10.16.01` out of DONE/PASSED.
