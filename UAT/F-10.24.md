# UAT — F-10.24 Workspace Teams

Story: `S-10.24.01`

Status: `UAT_PENDING`

Use official WorkOS authentication and PostgreSQL with Owner/Admin, two Member users and a Guest.

## Create and navigation

As a Member, create Teams such as Backend and Sales.

Expected: Teams appear in the shared workspace navigation. Existing visible Brain channels remain under **Unassigned channels**. No channel disappears, changes visibility or changes read/write access.

## Edit concurrency and authority

As the Team creator, edit its name/description. Keep a stale browser copy and submit the old revision after a newer edit.

Expected: the fresh edit succeeds; the stale edit returns conflict and does not overwrite the accepted value.

As another Member, attempt to edit/archive that Team.

Expected: fail closed. Repeat as Owner/Admin and confirm the privileged manager path succeeds.

As Guest, try to create or mutate a Team.

Expected: denied by the existing native-chat write role boundary.

## Archive / restore

Archive a Team.

Expected: it leaves the active Team list but no channel/message/evidence/DM/grant row is deleted. Use the management surface to restore it and confirm the same Team ID returns active.

## ACL invariance

Before Team create/edit/archive/restore, capture restricted-channel memberships and current Work Graph/evidence ResourceGrants. Repeat after each Team mutation.

Expected: there is no ACL/grant delta caused by Team metadata.

## Tenant isolation

With two organisations, try to edit the second organisation's Team through the first organisation path.

Expected: 404/fail-closed with no existence leakage.

## Acceptance gate

Record migration `20260920_0038` upgrade/downgrade/re-upgrade, focused backend tests, frontend source/build tests, delivery verifier and authenticated desktop/keyboard UAT. Keep S-10.24.01 `IN_REVIEW` until all executable evidence passes.
