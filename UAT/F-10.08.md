# F-10.08 Workspace Admin & Governance UAT

Story: `S-10.08.01`

Status: implementation in progress. No PASS is claimed until executable backend checks plus authenticated browser UAT complete.

## Scope

The Brain workspace provides an Owner/Admin-only administration surface for:

- organisation members and roles;
- integration lifecycle/health;
- AI provider and model governance;
- external API service/grant ownership, scopes, expiry and usage state.

The frontend must use authoritative backend permission checks. Browser code must never receive stored credential values, secret references, provider tokens or reusable Brain bearer tokens.

## Backend acceptance

1. Owner can read `/api/v1/organizations/{organization_id}/admin-center`.
2. Admin can read the same aggregate.
3. Manager/member/executive/guest cannot read the privileged aggregate unless their backend permissions are explicitly changed in a reviewed policy update.
4. Cross-tenant access returns no target organisation data.
5. Response includes safe member identity/role, integration status/health, AI provider/model status and API grant governance metadata.
6. Response never serializes `secret_ref`, raw credential dictionaries, API keys, OAuth tokens or integration external-account secrets.
7. `credential_present` is boolean metadata only.
8. Counts reconcile exactly with the visible aggregate rows.

## Frontend acceptance

1. Owner/Admin sees `Admin & governance` in the Brain workspace navigation.
2. Other roles do not trigger the privileged Admin Center backend request and do not see the navigation item.
3. Member/role list matches the backend aggregate.
4. Integration health and error state match backend data.
5. AI provider/model enabled/disabled state matches backend data.
6. API grant owner, environment, scopes, expiry, credential-present state and usage count match backend data.
7. No secret value is visible in rendered HTML, browser network responses or client JavaScript state.
8. Admin Center remains usable on desktop and narrow/mobile layouts.
9. Keyboard navigation and focus order cover the Admin navigation target and all future mutation controls.

## Mutation acceptance before completion

The read-first surface is not enough to mark the story DONE. Reviewed same-origin BFF mutations must later cover at minimum:

- membership creation/role governance using backend membership policy;
- integration revoke/health-safe lifecycle controls;
- AI provider/model enable-disable and provider revocation;
- API grant enable-disable, rotation/revoke and governance edits.

All destructive/credential-changing actions require explicit confirmation and server-side permission revalidation. Raw stored credentials must never be returned after creation/rotation.

## Required executable evidence

- Ruff for the Admin Center backend/test files.
- Pytest including `backend/tests/test_admin_center.py`.
- Frontend lint/build/source-contract tests.
- PostgreSQL-backed acceptance for aggregate queries.
- Authenticated WorkOS browser UAT with at least Owner, Admin and Member accounts.
- Network/browser inspection proving no secret serialization.

Until those pass, keep `S-10.08.01` out of DONE/PASSED.
