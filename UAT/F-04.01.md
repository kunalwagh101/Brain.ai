## Real-data backend validation

Use at least:

- one authorised public Slack channel with several messages
- one authorised private Slack channel with two test members
- one GitHub repository with a pull request or issue
- one restricted/private GitHub repository if available
- at least one resolved source identity
- one deliberately unresolved source identity
- one second Brain organisation for cross-tenant negative checks

Verify:

1. new supported Slack/GitHub canonical events create Work Graph projections automatically
2. replaying/reprocessing the same canonical event does not duplicate the evidence node or deterministic edges
3. Slack channel evidence maps to a track and preserves the canonical evidence reference
4. GitHub repository evidence maps to a project; PR/issue/other supported objects map to work items under that project
5. source-identity person nodes remain distinct from Brain-user person nodes
6. a current identity resolution creates exactly one `resolves_to` relationship to the correct Brain user
7. manual reassign replaces the old resolution link rather than leaving stale attribution
8. manual unresolve removes the resolution link without deleting the source-person or canonical evidence
9. every returned edge exposes type, source, evidence state, confidence and provenance
10. deterministic/manual facts are `VERIFIED`; any inference fixture/candidate remains visibly `INFERRED`
11. authorised users can create allowed manual project/track/work-item nodes and allowed organisational edges
12. manual person/identity edges are rejected
13. cross-tenant node/edge attempts are rejected and do not create rows
14. traversal is bounded and does not return another organisation's nodes
15. reconciliation processes only unprojected canonical events, honours its limit, and can be rerun without duplication
16. removing a user from the live private Slack channel authorisation removes graph traversal even though historical event ACL provenance still contains that user ID
17. restricted GitHub evidence is hidden until an explicit matching resource grant exists
18. Owner/Admin role alone does not bypass the established restricted-resource ACL contract
19. downgrade/forward-recovery procedure is understood and canonical/raw evidence remains sufficient to rebuild the graph

## Frontend / manual validation

When the Work Graph UI is available, verify:

- projects, tracks, work items, people and evidence are visually distinguishable
- verified and inferred relationships are clearly different
- confidence/provenance is available without exposing secrets or hidden source content
- restricted evidence is absent rather than partially leaked
- a revoked Slack/GitHub permission disappears from the visible graph after source authorization updates
- manual node/edge creation shows validation errors for unsupported relationship types
- empty graph, loading, permission-denied, validation-error and success states are understandable
- traversing from a project/work item makes the supporting evidence understandable without inventing progress or causality
