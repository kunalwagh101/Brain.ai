# UAT — F-10.19 Conversation History Pagination

Story: `S-10.19.01`

Status: `UAT_PENDING`

Use official WorkOS authentication and PostgreSQL.

## Native channel history

Seed more than 150 root messages in a channel. Open it as an authorised reader. Confirm only the initial recent window renders. Activate **Load older messages** repeatedly.

Expected: each request carries a positive `before_sequence` equal to the current contiguous history cursor, returns a bounded page in chronological order, and merges without duplicate message IDs. Composer text, open thread state and first-unread divider remain stable. When the last short/empty page is reached, Load older disappears.

Repeat in a restricted channel. Revoke the reader between page requests. The next request must fail closed and authoritative refresh must remove the channel/content.

## Direct-message history

Seed more than 250 Alice/Bob messages. As Bob, load older pages.

Expected: pages contain only Bob's current participant-visible epoch, chronological order has no gaps/duplicates among returned pages, and no Owner/Admin nonparticipant can request a page.

Revoke/downgrade Bob, restore and explicitly re-initiate the DM. Request older history using a cursor that would cover the prior epoch.

Expected: earlier-epoch messages remain hidden because the service always applies the new participant visibility floor.

## Cursor validation

Try `before_sequence=0`, negative values, non-numeric values and page limits above the server maximum through browser/API paths.

Expected: validation rejects safely; no query widens scope and no hidden identifier/content is returned.
