## Real-data backend validation

Prepare at least:

- one authorised public Slack channel with searchable messages
- one authorised private Slack channel with two test members
- one private Slack member removed during the test
- one public GitHub repository
- one restricted/private GitHub repository
- one explicit `github.repository` READ grant and one user without that grant
- a second Brain organisation for cross-tenant negative tests
- one source object that can be deleted or made unavailable
- at least ten labelled search questions with known relevant evidence

Verify:

1. run migration `20260907_0009` and confirm the vector extension and search table/indexes exist
2. run `python -m app.search_worker --once --batch-size 100` and confirm historical canonical events are projected without duplicates
3. run the worker with embeddings unconfigured/unavailable and confirm keyword projection still completes
4. search Org A and confirm no Org B identifiers, content or provenance appear
5. confirm an unauthorised public Slack channel does not appear until the channel is explicitly authorised
6. confirm a private Slack result appears only for a Brain user resolved to a currently listed Slack channel member
7. remove that Slack member/authorisation and confirm the same result disappears immediately on the next query
8. confirm private/internal GitHub evidence is absent for Owner/Admin without an explicit matching resource grant
9. add a READ grant and confirm the restricted GitHub evidence becomes searchable
10. revoke the integration and confirm its evidence disappears without deleting raw/canonical audit evidence
11. process a canonical delete event and confirm derived search content is removed/hidden
12. run keyword queries and record precision/recall on the labelled evaluation set
13. configure the embedding endpoint, run the worker, and confirm semantic queries can retrieve relevant evidence that does not share exact query terms
14. make the embedding endpoint unavailable and confirm hybrid search returns keyword results with `semantic_status=degraded`
15. confirm each result contains canonical event ID, provider, source/object reference, timestamp and provenance
16. confirm the embedding secret is stored only by secret reference and is absent from logs/database rows
17. run concurrent worker batches and confirm no duplicate document/embedding work is committed
18. measure p50/p95 search latency for keyword and hybrid modes at representative dataset size
19. perform migration downgrade in a disposable environment and confirm raw/canonical evidence remains sufficient to rebuild search after forward migration

## Frontend / manual validation

When the authenticated production frontend search surface is available, verify:

- loading, empty, permission-denied, degraded-semantic, error and success states are understandable
- results clearly show source/provenance without leaking hidden evidence
- keyboard navigation and focus states work
- screen-reader labels identify search input, mode and result links
- restricted/revoked evidence disappears rather than showing redacted fragments
- semantic degradation is visible and does not falsely claim AI/semantic success
- no preview/sample workspace data is presented as live company evidence
