# UAT — F-10.26 Channel Administration

Story: `S-10.26.01`

Status: `UAT_PENDING`

Use official WorkOS authentication with PostgreSQL. Exercise a channel creator, Owner/Admin, ordinary member, restricted-channel member and a second organisation.

## Rename and description

Create a Brain channel, then as the creator rename it and update the description.

Expected: the channel name/slug/description and `settings_revision` update atomically. The linked Work Graph track display name/channel slug update to the same current identity. Existing messages, RawEvents, CanonicalEvents and revisions are not rewritten.

Repeat the edit with the stale prior `expected_revision`.

Expected: conflict; the accepted settings are unchanged.

Try to submit a visibility conversion in the settings request.

Expected: rejected. Organisation↔restricted conversion is outside this story.

## Archive and restore

Archive an active channel.

Expected: it disappears from the default active sidebar, appears only in the manager-only Archived channels surface, remains readable to users who already have access, becomes non-postable, and keeps Team/group placement/history/evidence intact.

Restore it.

Expected: it returns to active navigation and posting follows the same pre-existing channel ACL.

## Restricted-member read/write access

Create a restricted channel and add a member as Read. Verify they can read but cannot post. Change that existing member to Read & write.

Expected: the existing membership row changes rather than being revoked/recreated; channel Work Graph/evidence ResourceGrants update consistently to WRITE and posting becomes available.

Change the same member back to Read.

Expected: ResourceGrants return to READ and posting becomes unavailable while read history remains.

## Authority and tenant isolation

As an ordinary non-creator member, guest, revoked user and a user from another organisation, try channel settings/archive/restore/member-access mutations.

Expected: fail closed; no hidden channel metadata or existence is leaked.

Verify channel creator and Owner/Admin authority. Verify an archived restricted channel still respects the exact same reader membership.

## Browser/security/accessibility

Inspect browser requests for settings, archive, restore and member access.

Expected: same-origin WorkOS routes, bounded JSON, server-side session token only, no bearer token/localStorage/sessionStorage/IndexedDB secret path.

Keyboard through Channel settings, Archived channels and restricted member access controls. Confirm visible focus, labelled form fields and alert errors.
