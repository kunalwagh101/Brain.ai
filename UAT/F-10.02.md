# UAT — F-10.02 Workspace Shell and Navigation

Status: **PENDING**

Story: `S-10.02.01 — Operate Brain through a Slack/Discord-style permission-aware workspace`

No PASS is claimed until the executable frontend/backend checks and authenticated browser scenarios below actually run successfully.

## Preconditions

- official WorkOS frontend auth path is available for browser UAT;
- Brain backend points to a real migrated PostgreSQL environment;
- test organisation contains at least two visible projects, one visible track and one restricted project/track that the test user must not see;
- a second organisation exists for cross-tenant negative testing;
- no sample credentials or preview-header authentication is used.

## Automated contract checks

1. `backend/tests/test_workspace_navigation.py` executes successfully.
2. Cross-tenant workspace navigation returns no target-organisation fields.
3. Restricted project/track labels do not appear in the JSON response for an unauthorised user.
4. Frontend lint/build/tests execute with the real dependency lockfile.
5. Production workspace imports and renders without sample fixture data.

## Browser scenarios

### 1. Normal member can enter Brain

- Sign in as a normal Member.
- Open the production root workspace.
- Verify the workspace itself loads even though Company Pulse/Executive Overview is unavailable.
- Verify organisation name and current role come from the authenticated server-side membership.

Expected: the member is not rejected merely for lacking executive/audit permission.

### 2. Permission-aware sidebar

- Confirm visible Work Graph tracks appear under **Tracks**.
- Confirm visible projects appear under **Projects**.
- Confirm the restricted project/track name is absent from navigation, counts and badges.
- Grant access to the restricted resource and reload.
- Revoke access and reload again.

Expected: navigation follows current permission state; revoked content disappears.

### 3. Cross-tenant isolation

- Sign in as an Org A member.
- Request an Org B organisation ID through the route/query mechanism used by the production frontend.

Expected: Org B is unavailable and no Org B project/track names appear anywhere in rendered HTML or browser data responses.

### 4. Executive capability is inside the workspace

- Sign in as Owner/Admin/Executive.
- Verify Company Pulse appears.
- Sign in as Member.
- Verify the workspace still loads while the role-gated Company Pulse is replaced by the bounded role notice.

Expected: Executive Overview is permission-gated without becoming a workspace-wide gatekeeper.

### 5. No fake collaboration controls

- Inspect the shell before native chat/evidence/BFF stories are complete.

Expected: no working-looking chat composer, file list or Ask Brain action points to a missing/insecure endpoint. Planned surfaces are clearly non-interactive until their stories are wired.

### 6. Responsive and keyboard navigation

- Desktop width >= 1180 px: verify workspace rail + navigation + main + context region.
- Tablet width ~820–1180 px: verify context rail collapses without losing main navigation.
- Small/mobile width <= 560 px: verify the primary workspace rail becomes the compact top navigation and content remains usable.
- Keyboard-only: verify skip link, links and interactive controls have reachable focus states and sensible order.

Expected: no horizontal content trap, inaccessible hidden navigation or keyboard dead-end.
