# UAT — F-10.18 DM Unread & Resume

Story: `S-10.18.01`

Status: `UAT_PENDING`

Use the official WorkOS-authenticated workspace, PostgreSQL and three organisation members: Alice, Bob and an Owner who is not a participant in Alice/Bob's DM.

## Per-participant unread

1. Alice opens a 1:1 DM with Bob.
2. Alice sends two messages while Bob is not viewing the conversation.
3. Inspect both users' DM lists.

Expected: Alice has zero unread from her own sends. Bob has unread count 2, latest-message ID = Alice's second message, first-unread ID = Alice's first message. The nonparticipant Owner has no Alice/Bob conversation.

## Divider, jump and mark-read

1. Bob opens the DM.
2. Before/while the server refresh completes, inspect the message pane.
3. Activate **Jump to unread** by keyboard and pointer.

Expected: one accessible **New messages** divider appears immediately before Alice's first unread message. Jump focuses and scrolls to it. The persisted unread badge clears through Bob's own monotonic read cursor, but the mounted panel keeps the captured divider during that open session.

## Partial and stale read

Using API/test tooling, mark Bob read only through the first of two unread messages, then attempt an older/stale mark after marking through the second.

Expected: after the partial mark the next message is still first unread; after the latest mark unread is zero; the stale mark never moves the cursor backwards.

## Exact target outside initial window

Seed more than the initial DM message window while keeping Bob's cursor before an older unread target, then activate **Jump to unread**.

Expected: the browser performs a same-origin GET to the exact DM-message route, WorkOS stays server-side, the backend rechecks participant access, and the target is inserted/focused without exposing a reusable bearer token.

## Visibility epoch

1. Create an old Alice/Bob private message.
2. Downgrade/remove Alice's DM capability and then restore it.
3. Explicitly re-initiate Alice/Bob DM.
4. Inspect Alice unread state and try the old exact message ID.
5. Bob sends a new message.

Expected: Alice starts with zero unread at the new visibility floor; old exact history remains 404/hidden; only Bob's new-epoch message becomes unread.

## Nonparticipant and revocation

The Owner/Admin/Executive who is not a participant must not be able to list/read the conversation, exact target, or mark it read. A revoked participant must immediately lose list/read/read-cursor access. The still-authorised participant may keep their allowed history-only view.
