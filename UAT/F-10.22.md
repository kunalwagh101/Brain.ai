# UAT — F-10.22 Thread Unread & Resume

Story: `S-10.22.01`

Status: `UAT_PENDING`

Use official WorkOS authentication and PostgreSQL with two authorised channel users.

## Independent thread state

Open a channel containing two active threads. Open only thread A, then have the other user reply in both A and B.

Expected: thread A has its own read cursor and new replies after that cursor become unread. Thread B has no personal thread-unread state until the user opens it. Channel-level read state does not silently mark either thread read.

## First unread and monotonic reads

After establishing thread state, create two replies from the other user. Open the thread.

Expected: the root shows the exact unread count; the thread pane captures one **New replies** divider at the first unread reply and **Jump to unread** focuses it. The persisted cursor advances through the latest visible reply. An older/stale mark-read cannot move the cursor backwards. The user's own replies do not count as unread.

## Pagination and exact recovery

Put the first unread reply outside the initial reply window and activate Jump to unread.

Expected: Brain recovers the exact reply through the existing permission-aware same-origin message route, validates that it belongs to the current root, inserts it without duplicating history and focuses the divider.

## Retraction / revocation

Retract an unread reply before it is read.

Expected: it disappears from thread unread count/first-unread state. Then revoke the reader from a restricted channel.

Expected: root/thread unread and mark-read requests fail closed and no stale unread metadata remains after authoritative refresh.
