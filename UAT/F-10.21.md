# UAT — F-10.21 Thread History Pagination

Story: `S-10.21.01`

Status: `UAT_PENDING`

Use official WorkOS authentication and PostgreSQL.

## Long thread

Seed more than 150 replies under one visible thread root. Open the thread and activate **Load older replies** repeatedly.

Expected: each request sends a positive `before_sequence`, returns only replies under the same root, preserves chronological order and creates no duplicate reply IDs. Composer text, pending attachments, focused reply and any first-unread divider remain stable.

## Live refresh after older pages

After loading older pages, have another user add/edit/retract a recent reply.

Expected: the 4-second thread refresh merges recent state into the existing history rather than replacing the loaded older pages.

## Permission and lifecycle

Repeat in a restricted channel, revoke the reader between page requests and confirm the next request fails closed. Retract a root that already has replies and confirm historical replies remain pageable under the existing tombstone contract while new replies stay disabled.

## Validation

Try zero/negative/non-numeric cursors and over-limit page sizes.

Expected: browser/BFF/backend validation rejects safely; no hidden reply identifier or content is exposed.

## Acceptance gate

Record focused backend tests, frontend source/build checks and delivery-verifier output. Keep S-10.21.01 `IN_REVIEW` until authenticated long-thread/revocation UAT passes.
