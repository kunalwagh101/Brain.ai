# UAT — F-02.04 Meeting/document evidence

Story: `S-02.04.01`

Status: **PENDING**. These are acceptance instructions, not evidence that the feature passed.

## Preconditions

- Brain API/database migrations are deployed.
- Test users belong to one isolated organisation.
- Use representative non-secret files first.
- Use the same commit for backend and UAT evidence.

Set:

```bash
export BASE_URL="https://<brain-api-host>/api/v1"
export ORG_ID="<uuid>"
export ACCESS_TOKEN="<member-access-token>"
```

## UAT-1 Organisation text/transcript upload

Upload a real UTF-8 meeting transcript or document:

```bash
curl -sS -X POST \
  "$BASE_URL/organizations/$ORG_ID/evidence/uploads" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Idempotency-Key: uat-f0204-001" \
  -F "kind=transcript" \
  -F "visibility=organization" \
  -F "title=Weekly product review" \
  -F "file=@./weekly-review.txt;type=text/plain"
```

Pass only if metadata returns `active`, source SHA-256 and non-zero chunk/extracted-character counts, and the API never returns the original file bytes.

## UAT-2 PDF and DOCX extraction

Upload one text-bearing PDF and one DOCX with paragraphs/table content. Search for exact phrases known to exist in each source.

Pass only if the phrases are found with `source_provider=generic_upload`, the citation/search provenance contains the source hash/source ID/chunk position, and no unrelated source content appears.

A scanned-image PDF with no extractable text must fail explicitly; OCR is not an implicit fallback in this story.

## UAT-3 Restricted evidence

Upload a source with `visibility=restricted` as User A. Search and read its metadata as User A and User B.

Pass only if User A can retrieve it and User B receives neither content nor restricted metadata. Role changes must not silently widen restricted access without an explicit resource grant.

## UAT-4 Idempotency

Replay the exact upload with the same `Idempotency-Key`.

Pass only if the same source ID is returned and no duplicate canonical/search evidence appears. Repeat with different bytes under the same key; the request must return conflict and must not overwrite the first source.

## UAT-5 Delete source

Delete a test source:

```bash
curl -sS -X DELETE \
  "$BASE_URL/organizations/$ORG_ID/evidence/<source-uuid>" \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Pass only if:

- the governed source-object deletion completes;
- the source becomes `deleted`;
- original `raw_content` is cleared from active storage;
- its canonical/search derivatives no longer exist/return;
- subsequent Search and Ask Brain requests cannot recover the deleted text;
- the security audit records metadata/hashes only, not document content.

If legal hold is enabled, deletion must fail closed instead of bypassing the hold.

## UAT-6 Revoke generic adapter

In an isolated test organisation, move the generic evidence integration out of ACTIVE state and repeat a known search.

Pass only if all evidence owned by that connection disappears from Search immediately. Do not use a production organisation for this destructive lifecycle check.

## UAT-7 Limits and malicious inputs

Verify:

- >10 MB upload returns a bounded rejection;
- unsupported binary type is rejected;
- encrypted PDF is rejected;
- oversized/expanding DOCX is rejected;
- guest cannot upload/delete;
- a different tenant cannot list/read/delete the source;
- filename/path input does not cause filesystem reads outside the uploaded payload.

## UAT-8 Downstream consumers

After uploading a meeting note containing one known decision and one known blocker, run Search, Ask Brain and the decision-memory reconciliation on the same authorised user.

Pass only if the downstream systems cite the generic evidence provenance and preserve the same permission boundary. This downstream UAT cannot itself mark S-05.01/S-05.02/S-04.02 DONE while their own deferred gates remain outstanding.
