# UAT — F-10.17 First-Unread Divider & Jump to Unread

Story: `S-10.17.01`

Status: `UAT_PENDING`

## Preconditions

Use the official WorkOS-authenticated workspace with PostgreSQL and at least two active users in one organisation. Create one organisation-visible channel and one restricted channel. Keep browser developer tools open so same-origin requests can be inspected.

## Root-message boundary

1. User A opens the channel and reads through the latest message.
2. User B posts two new root messages.
3. User A returns to the channel.
4. Confirm one **New messages** divider appears immediately before User B's first new root and the header shows **Jump to unread**.
5. Activate **Jump to unread** with keyboard and pointer. Confirm focus/scroll lands on the divider.
6. Confirm the channel unread badge clears through the existing read cursor, but the divider remains during that open-channel session rather than disappearing on the router refresh.

Expected: the first-unread boundary is stable for the open panel, there is at most one divider, and no second unread state is persisted.

## Thread-reply boundary

1. User A reads through a root message.
2. User B replies to that root after User A's cursor.
3. User A opens the channel and activates **Jump to unread**.
4. Confirm Brain opens the owning thread, renders the divider immediately before the exact unread reply and focuses that divider.
5. Retract the root while keeping the existing reply history. Repeat with a later unread reply and confirm the tombstoned root does not block navigation to the valid reply.

Expected: a reply can be the exact first unread item; preserved replies remain reachable under a retracted root.

## Older target outside initial root window

1. Seed enough newer root messages so the exact first unread root is not in the initial message window.
2. Keep User A's read cursor immediately before that target.
3. Open the channel and activate **Jump to unread**.
4. Inspect the network request.

Expected: the browser performs a same-origin GET to the existing exact-message route, the server revalidates membership/channel access, the target is materialised without a new content store, and the divider is focused.

## Own-message and retraction rules

1. User A posts a message after their own cursor. Confirm it does not become User A's first unread item.
2. User B posts a message; confirm it becomes User A's first unread item.
3. Retract that message before User A jumps or while the panel is open.

Expected: retracted content is not presented as unread; the stale divider/jump disappears once the current state observes the retraction.

## Restricted-channel revocation

1. Give User A read access to a restricted channel and create an unread message from User B.
2. Confirm User A receives a first-unread ID while authorised.
3. Revoke User A's restricted-channel membership.
4. Refresh unread summaries and attempt the exact message route.

Expected: the restricted channel disappears from unread summaries and exact-message recovery returns no hidden content. No stale unread boundary leaks message identity/body in the UI.

## Security and accessibility

Confirm the browser contains no reusable backend bearer token in local/session storage and jump/read calls are same-origin WorkOS routes. Tab to **Jump to unread** and confirm visible focus. The divider has an accessible separator/name and receives focus after jumping.
