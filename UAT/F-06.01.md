## Backend / real-provider validation

1. Run `alembic upgrade head` and confirm revision `20260907_0011` applies.
2. Configure `BRAIN_AI_PROVIDER_ALLOWED_HOSTS` with the exact approved provider hostname in the production-like environment.
3. As a Member, attempt `POST /ai/providers`; confirm 403 and confirm no provider secret is created.
4. As Owner/Admin, create a provider with a real test credential. Confirm the API response contains no credential or secret reference.
5. Inspect PostgreSQL and confirm the provider row contains only a secret reference and non-secret metadata.
6. Inspect AWS Secrets Manager and confirm the provider credential exists at the expected AI-provider path.
7. Create one approved model; list providers/models from the same organisation.
8. From another organisation, attempt to read/use those IDs; confirm no foreign metadata is returned.
9. Invoke the model as an authorised Member using a non-sensitive test prompt.
10. Confirm the returned answer is real provider output and the provider receives exactly one request.
11. Inspect `ai_request_records`: confirm org/user/provider/model/status/latency/provider request ID/token counts (when provider supplies them) are present.
12. Confirm the prompt/system/completion text is absent from `ai_request_records` and application logs.
13. Invoke with valid project/work-item attribution and confirm the Work Graph node is recorded.
14. Attempt attribution to another organisation or inaccessible restricted node; confirm failure before provider execution.
15. Disable the model and retry; confirm no provider call occurs.
16. Re-enable model, disable provider and retry; confirm no provider call occurs.
17. Force provider timeout/5xx/429 in a test environment. Confirm the request row becomes `failed`, error code is bounded/safe, and upstream response body is not exposed.
18. Revoke the provider. Confirm provider becomes unavailable before/while secret deletion is attempted and future calls fail closed.
19. Confirm the credential is scheduled for deletion and the provider database record no longer exposes a usable secret reference after successful revocation.
20. Run downgrade in a disposable environment and confirm AI gateway tables are removed without affecting organisations, canonical evidence, Work Graph, search or decision memory.

## Security / egress validation

- In production mode, attempt an `http://` provider URL: must fail.
- Attempt a hostname not in `BRAIN_AI_PROVIDER_ALLOWED_HOSTS`: must fail.
- Validate a private/link-local provider address through a unit-level URL check only; it must fail before any network request is attempted.
- Confirm provider URL userinfo (`https://user:pass@host/...`) is rejected.
- Confirm provider credentials and prompt content are absent from normal/error logs.

## Frontend/manual validation

When the real administration UI exists:

1. Open AI provider settings as Member; management controls must not be available/usable.
2. Open as Owner/Admin; add a provider/model using the real configuration workflow.
3. Check loading, duplicate-provider, invalid URL, secret-store failure, disabled and revoked states.
4. Trigger a real AI request from the UI path that will ultimately be used by Ask Brain or another feature.
5. Confirm provider/model identity and failure status are understandable without exposing credentials.
6. Confirm project attribution is visible when supplied and stays blank when unknown.
7. Confirm revocation immediately prevents new requests.
