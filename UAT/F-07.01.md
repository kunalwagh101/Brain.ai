## UAT-1 Unconfigured progress is unknown

Open a visible project that has Work Graph activity/evidence but no `project_progress_items` configuration.

Pass only if:

- `progress_percent` is `null`;
- `progress_basis` is `unconfigured`;
- Brain does not derive a percentage from PR count, message count, commits, AI output or evidence volume.

## UAT-2 Deterministic weighted progress

Configure two linked work items:

- item A: `done`, weight 3;
- item B: `in_progress`, weight 1.

Pass only if the visible project percentage is exactly `75.0` and the response exposes both contributing work items, their states and weights.

Change the states/weights and independently recompute the percentage. The API result must match the deterministic formula in `docs/PROJECT_STATUS.md`.

## UAT-3 Unrelated work cannot affect progress

Attempt to configure a Work Graph `work_item` that is not linked to the project.

Pass only if the mutation is rejected and the project percentage remains unchanged.

## UAT-4 Candidate blocker is not a fact

Link evidence containing an explicit blocker and run the decision-memory extractor.

Before human confirmation:

- the memory appears only as a candidate;
- project status is not changed to `blocked` solely because of the candidate.

After an authorised human confirms that blocker:

- it appears in `active_blockers`;
- project status becomes `blocked` unless a stronger deterministic state rule applies;
- source/canonical/search identifiers remain available for inspection.

## UAT-5 Confirmed decision with evidence

Confirm a decision associated with visible project evidence.

Pass only if it appears in `confirmed_decisions` and the project snapshot exposes the underlying authorised evidence/provenance.

## UAT-6 Current permission boundary

Create restricted project evidence visible to User A but not User B.

Pass only if User B receives none of its:

- evidence title/content-derived metadata;
- source/canonical/search IDs;
- decision/blocker memory;
- restricted Work Graph node details.

Remove User A's grant and repeat without rebuilding the dashboard. The restricted material must disappear immediately.

## UAT-7 Revocation/deletion

Use evidence from an active integration in a project snapshot, then revoke/delete it through the real source lifecycle.

Pass only if the project read no longer exposes revoked/deleted evidence or memory derived from evidence that is no longer authorised.

## UAT-8 Generic meeting/document evidence

Upload a representative meeting transcript/document using F-02.04, relate its evidence node to the project through the Work Graph, and run memory extraction if it contains an explicit decision/blocker.

Pass only if the project snapshot can show the authorised generic-upload provenance and the corresponding memory while preserving current ACL checks.

## UAT-9 Cross-tenant isolation

Create Org A and Org B with deliberately distinctive project/evidence markers. As an Org A user, request the known Org B project ID and list projects.

Pass only if no Org B project, progress row, evidence, blocker, decision or provenance is returned.

## UAT-10 Audit trail

Create, update and delete a structured project progress item.

Pass only if the governance audit trail records the actor, project/work-item IDs, structured state/weight where applicable, outcome and request context without secret data.

## UAT-11 Frontend/manual quality

Once the production frontend exists, verify that an authorised leader can:

- choose a project;
- distinguish deterministic progress from unconfigured/unknown progress;
- inspect the structured work items behind the percentage;
- see confirmed blockers and decisions separately from candidates;
- open source evidence/provenance;
- understand when content is absent due to permissions without exposing hidden-resource existence;
- use the view with keyboard navigation and visible focus.

The current preview UI cannot satisfy this gate.
