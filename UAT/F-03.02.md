## Real-data validation

Use at least these source examples:

- Slack public-channel message
- Slack private-channel message
- GitHub public-repository event
- GitHub private-repository pull request or issue
- GitHub historical/backfill item

For each example, inspect the raw event and canonical event and verify:

1. exactly one canonical event exists for one raw event
2. `organization_id` and integration connection are correct
3. schema version is explicit
4. event type/action describe the source action correctly
5. actor source identity is preserved without pretending it is already a resolved Brain user
6. object type and stable external ID are correct
7. occurrence/source timestamp is reasonable for the source record
8. source provider/event ID/event type are preserved
9. source visibility and ACL evidence match the source permissions
10. provenance points to the raw event and its payload SHA-256
11. useful provider metadata is preserved without copying credentials/secrets

## Failure / quarantine validation

1. Exercise an unsupported source event in a controlled test environment.
2. Confirm the raw event remains intact.
3. Confirm the raw event becomes `QUARANTINED` with a bounded error code.
4. Confirm no misleading canonical event is produced.
5. Correct/support the mapping in a test branch or controlled test path, reprocess it, and verify the original raw evidence is sufficient to recover.

## Cross-provider consistency

Compare one Slack message event and one GitHub engineering event. Confirm both expose the same canonical dimensions:

- organisation
- actor
- action
- object
- source
- occurred_at
- permissions/visibility
- provenance
- schema version
- provider metadata

The values will differ, but the contract must not require downstream code to understand the original provider just to identify these dimensions.

## Frontend / manual validation

Where canonical activity is surfaced in the UI, manually confirm:

- correct source badge/provider
- understandable action text
- correct project/repository/channel context where available
- source/evidence link or provenance representation
- private/restricted evidence is not shown to an unauthorised user
- quarantined data is not presented as normal company activity
- loading/empty/error states are understandable
