# Increment 2 Retrospective — RBAC and Resource ACL

Date: 2026-09-06
Story: S-01.03.01

## Outcome

Brain now has one server-side authorization contract for organisation roles and restricted resources. Protected resource access can be rejected before endpoint, connector, search, LLM or tool code executes.

## What worked

- Converting route-specific owner/member checks into a reusable policy layer reduced the chance that future integrations invent inconsistent permission rules.
- Testing all six roles at the HTTP boundary caught policy behaviour where it actually matters.
- Separating role capability from explicit resource grants prevents broad administrator roles from silently exposing every private channel or document.
- The delivery verifier kept the story in WIP until evidence was attached.

## What CI caught

The first PR run failed only on two Ruff issues in the new test file: import ordering and a nested `with`. Both were fixed without changing authorization behaviour. The next run passed lint and the full 34-test backend suite.

## Security decisions retained

- Non-members receive 404 to avoid tenant/resource disclosure.
- Role-denied members receive 403.
- Restricted resources without a matching grant receive 404.
- Only owners may assign owner/admin roles.
- Slack DMs remain outside the production MVP; private channels are opt-in.
- Authorization and ACL mutation hooks emit structured metadata but never source content or secrets.

## Follow-up

Persistent immutable audit storage belongs to S-09.02.01. The next product dependency unlocked by this increment is S-02.01.01, the scoped integration connection framework, once OQ-003 (production secrets manager) is resolved.
