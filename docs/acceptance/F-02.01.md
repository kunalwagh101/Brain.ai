# F-02.01 Integration Framework — UAT Script

Status: PENDING

## Real-data backend validation

Use a non-production test organisation and test provider account.

1. Configure real WorkOS authentication for the test environment.
2. Configure an AWS workload identity that can access only the Brain test secret prefix.
3. Create an integration using realistic OAuth/API credentials through the backend/API flow.
4. Verify the API response never returns credential values or `secret_ref`.
5. Verify PostgreSQL contains only connection metadata plus an AWS secret reference.
6. Verify AWS Secrets Manager contains the credential under the expected environment/organisation/provider/connection path.
7. Attempt the same organisation/provider/account twice and verify duplicate creation is rejected.
8. Verify Owner/Admin can manage the connection; Member cannot; cross-tenant user sees no connection data.
9. Exercise a connector-worker test call using the stored credential and record a realistic sync cursor/health result.
10. Revoke the connection and verify it becomes non-syncable before/while the secret is retired.
11. Verify the old credential can no longer be used by Brain after revocation.
12. Exercise migration upgrade and rollback in a disposable database; confirm the credential-retirement runbook prevents orphaned test secrets before rollback.

## Frontend/manual validation

When the integration UI exists:

1. Open Settings / Integrations as Owner or Admin.
2. Check loading and empty states.
3. Connect a real test provider account.
4. Verify provider name, account, scopes and connection health render correctly without exposing secret material.
5. Check duplicate/error state.
6. Check Member access-denied state.
7. Revoke the connection from the UI and verify the state updates to revoked.
8. Refresh/re-login and verify state persists.
9. Confirm accessible labels, keyboard navigation and responsive layout.
